# M5.173 修复说明（TBD run number）

> 起因：报告《小玉-交接报告-M5.172》描述的绘制链路与真机实际执行的不是同一条；
> 线上表现为「头甲空白 / 血量空条 / 队伍 0 / 一下有一帧一下没有 / 主界面按钮过多」。

---

## 1. 根因（一句话）

属性读取全写在不被调用的两处：`MFUEReader.enumerateActors`（0 调用）与
`MFGameReader.readEntitiesWithCamera`（门条件 `rootObjectBase != 0`，生产代码从不赋值）。
真机每帧走的是 `MFDrawingLayer.acquireUE4FrameWithSize`，它只读坐标、类名、`isBot@0xE60`。

所以：**不是偏移错，是读数没接到活路径上。** 血量恒 0（空条）、头甲恒「头- 甲- 包-」、
队伍恒 0、UIN 恒 0、手持恒「空手」、自己也不筛。

---

## 2. 改了什么

### 2.1 把属性接到现役路径（`HUD/MFDrawingLayer.mm`）

新增 `fillPersonFields:` / `readPersonFields:` / `refreshPersonPosition:`：

| 字段 | 偏移（真机已验证） | 频率 |
|---|---|---|
| 坐标 | `actor+0x180` → `+0x220` | 每人每帧（≤20 人，2 次读） |
| 自己 | `== gMFUELocalPawn`，另有距离 <2m 兜底 | — |
| 死亡 | `actor+0xDC8` 首字节非 0 → 丢 | 1.2s |
| 观战/未激活 | `PS+0x4C0 & 1` → 丢 | 1.2s |
| 队友 | `actor+0x10C0` → `+0x108 == gMFUELocalTeam` 且有 PS → 丢（菜单可反） | 1.2s |
| 人机 | `+0xE60`，另 `PS==0` 判人机 | 1.2s |
| 血量 | `actor+0x10B8` → `+0x258` float | 1.2s |
| 头/甲/包 | `actor+0x24E0` 整块 2KB 扫描 + 十进制 ID 解码 | 1.2s |
| 队伍 | `+0x10C0 → +0x108` | 1.2s |
| 手持 | `+0x1020` → `+0x4D8`/`+0x588` → `+0x838` | 1.2s |
| UIN | `PS+0x320` | 1.2s |
| 名字 | `PS+0x470(指针)/+0x478(Num)` UTF-16 | 1.2s |

缓存按 actor 键、TTL 1.2s，`>512` 条目时清理过期项。

### 2.2 血量显示（三处）

1. 现役路径此前根本不写 `e.health`，默认 0 → 血条按 0 画 = **空条**；
2. 新建实体统一 `e.health = -1`（未知→满格），只有真读到才按比例画；
3. `drawEntity` 里比例钳到 `[0,1]`，>100（带甲）不再越界；数字显示条件从「0..100」改成「≥0」。

### 2.3 「一下有一帧、一下没有」——五处止血

| # | 旧行为 | 现在 |
|---|---|---|
| 1 | 链解析每秒重解，失败即 `return NO` → **整帧空** | 失败沿用上次成功结果，宽限 3s |
| 2 | `Pawn` 读失败当断链 → 死亡/重生/换人期间**整屏空** | 非致命，只让自过滤退化为距离兜底 |
| 3 | 相机读失败 → 整帧空 | 沿用上一帧 0.5s |
| 4 | Actor 指针数组先清空再读，读失败 → **空 1 秒** | 读成功才替换 |
| 5 | 分类可用性每帧重算，true/false 来回翻 → 满屏框↔只有人 | 一旦可用即锁定（sticky） |

附带：
- 相机角度**归一化**（yaw 可能是 0..360，旧判据 `|yaw|≤180.5` 会按朝向整帧拒掉）；
- FOV 判据 20..150 → 5..175（开镜/载具/过场不再被拒）；
- `kMFUEActorTTL` 1.0 → 2.0（掉帧时轮转一圈可能 >1s，旧值会让条目同时过期 → 闪一下全没）；
- `kMFUEActorBudgetPerFrame` 320 → 192，逐帧内核读从 ~640 降到 ~424；
- `readCamera` 里每帧一次的 `NSLog` 改成 5 秒一次（60Hz 打日志本身就会卡）；
- `MFHUDTargetBinding` 重试间隔 5.0 → 2.0s（每次身份失败都会关读取门 = 黑屏）。

### 2.4 主界面彻底精简（`App/RootViewController.mm` 重写）

原五节 14 行（启动内核 / 内核设置 / 环境检测 / 模块定位 / UE4 解析 / 游戏自检 /
扫描模块 / 导出模块 / 清理残留 / 清理 Key / 防封 / 游戏模式 / 系统自检 / 导出诊断）
→ 三节：

```
状态   悬浮窗（运行中 PID / 未启动）
操作   启动悬浮窗 / 结束悬浮窗 / 取消启动
关于   版本+构建戳 · HUD 日志
```

删除文件：`MFProcessViewController.{h,mm}`、`MFResidueViewController.{h,mm}`（共 1127 行，仅主界面在用）。

## 3. 怎么验（装新包后）

1. 训练营进图，看**「头N 甲N 包N」**——N 与目标实际装备一致；
2. 看**血条**：出生满格，中枪掉格，名字后面有血量数字；
3. 走一圈：**不应再整屏闪空**；死亡/重生那两秒也不该全黑；
4. **自己**不出框（距离兜底 2m）；
5. 队友默认不画，HUD 菜单「队友」可反；
6. 菜单里 `人机显示 / 骨骼 / 手持` 默认是关的，要看得自己打开。

## 4. 如果还是不显示

| 现象 | 先查 |
|---|---|
| 头甲仍「头- 甲- 包-」 | 装备组件 `+0x24E0` 或 2KB 扫描没命中 → 用 `tools/frida_equip.js` 对同一 actor 复核 |
| 血量仍满格不变 | `+0x10B8 → +0x258` 变了（版本更新）→ 见 `MFUEOffsets.h` 常量注释 |
| 名字空 | `PS+0x470/+0x478` 指针在前布局变了 |
| 整屏仍闪 | 拉 `mf-live.txt` 看 `binding.stage` 是否在 `ready` 与 `task-port/identity` 之间跳 |
