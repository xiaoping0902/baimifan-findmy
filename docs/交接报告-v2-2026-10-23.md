## 5. 关键技术发现

### 5.1 ★★★ GWorld 静态偏移的十六进制转换是错的

mingyun 反编译原文是十进制：

```c
v8     = Read<unsigned long>(sLibBase + 395003104);   // GWorld
sGName = sLibBase + 389510848;                        // GNames
```

早期文档转十六进制时**两个都算错**，复刻版照抄：

| 常量 | 十进制原文 | **正确** | 旧值（错） | 差 |
|---|---|---|---|---|
| GWorld | 395003104 | **`0x178B44E0`** | `0x178AA5E0` | 0x9F00 |
| GNames | 389510848 | **`0x173776C0`** | `0x1739D0C0` | 0x25A00 |

**为什么长期没发现**：偏移量级约 377 MB，两个值看着都「合理」，量级检查全过。

**交叉验证**：Dumper-7 SDK 给的是带 image base 的绝对地址：

```
GWorld = 0x1178B44E0  →  减 0x100000000  =  0x178B44E0   ✓
GNames = 0x1173776C0  →  0x173776C0                       ✓
```

**修复**：`MFUEOffsets.h` 的 `kMFUE_DefaultGWorld` / `kMFUE_DefaultGNames`，同时保留十进制字面量便于复核。`MFUEProfile` 存盘 key 升到 `mf.ue.profile.v2`（旧快照里是错值）。

### 5.2 ★★ 两条数据链，绘制层原来接错了

| 链 | 起点 | 能否自动建立 |
|---|---|---|
| `MFUEReader` | 模块基址 + GWorld 静态偏移 | **能** |
| `MFGameReader` | `rootObjectBase` / `entityArrayBase` / `lootArrayBase` 三个**手工校准**绝对地址 | 不能（全工程没有 UI 能给这三个赋值） |

原来接的是 `MFGameReader` → `cameraOK` 恒 false → **永远画不出来**。

**修复**：`acquireFrameWithSize:` 三级优先：外部数据源 → 已校准链 → UE4 链。

### 5.3 ★★★ task_for_pid 在 A12+/iOS 15+ 被 PPL 挡死

真机「一键开始」分项探测（iPad14,4 / 16.1）：

```
✓ 自己(603)         task port = 0x203      ← 假信号！对自己永远成功，不需要权限
✗ launchd(1)       kr=0x5 KERN_FAILURE
✗ SpringBoard(32)  kr=0x5
✗ 游戏(601)        kr=0x5
processor_set_tasks 全线 kr=0x4 KERN_INVALID_ARGUMENT
```

环境检测佐证：

```
✓ 沙盒豁免 4/4 可读      ← no-sandbox 生效，entitlements 机制本身是工作的
· 运行身份 uid=501       ← 非 root
```

**结论**：`no-sandbox` 走 sandbox 层能过；`task_for_pid-allow` 走 kernel 层被 PPL 挡。**连 launchd/SpringBoard 都拿不到，所以不是游戏反作弊，是我们的权限不被内核认可。**

**错误码对照**：

| kr | 含义 |
|---|---|
| `0x2` KERN_PROTECTION_FAILURE | 权限不足 |
| `0x4` KERN_INVALID_ARGUMENT | pid 不存在 / 无此 task |
| `0x5` KERN_FAILURE | taskgated 按代码签名拒绝，或目标有 CS_HARD |

## 6. ★★★ 游戏闪退的完整诊断（本轮重点）

### 6.1 现象

- 20:30 左右起：**进训练营就闪退**
- 20:44：**越狱和不越狱（只是重启）都 1 分钟内闪退**
- 用户描述：**「突然回到桌面」**（不是黑屏重开，不是卡死）

### 6.2 排除过程（按时间顺序，每条都有证据）

**① 以为是 Frida 被 ACE 检测**

理由：`frida-server` 是 root 常驻进程，ACE 扫进程会看到。

**测试**：重启 iPad，不点 Dopamine 的 Jailbreak → 进游戏。

**结果**：**还是闪退** → 排除 Frida。

**② 查崩溃日志——没有**

```powershell
python -X utf8 -m pymobiledevice3 crash ls /Retired
```

`/Retired` 里唯一与游戏相关的：

```
DeltaForceClient.diskwrites_resource-2026-10-23-194404.ips
```

**没有** `DeltaForceClient-<时间>.ips` 崩溃报告。

**③ 查 diskwrites 日志——不是死因**

文件内容关键行：

```
Event:            disk writes
Action taken:     none          ← ★ 系统没有采取任何行动
Writes:           1073.75 MB of file backed memory dirtied over 260 seconds
                  (4125.09 KB per second average), exceeding limit of 12.43 KB/s
Writes limit:     1073.74 MB
Writes duration:  260s
Footprint:        478.11 MB -> 1640.72 MB (+1162.61 MB) (max 1784.28 MB)
```

**`Action taken: none`** = 只是记录，没杀。**排除磁盘写入。**

（但这行数字有用：游戏内存峰值 1.78 GB。）

**④ 查 Jetsam（内存杀进程）——没有受害者**

用脚本解析 6 个 `JetsamEvent-*.ips`：

```
JetsamEvent-2026-10-23-170930  largestProcess=DeltaForceClient  victims: (空)  reasons: []
JetsamEvent-2026-10-23-173106  largestProcess=WeChat            victims: (空)
JetsamEvent-2026-10-23-173537  largestProcess=WeChat            victims: (空)
JetsamEvent-2026-10-23-173638  largestProcess=WeChat            victims: (空)
JetsamEvent-2026-10-23-175826  largestProcess=DeltaForceClient  victims: (空)  reasons: []
JetsamEvent-2026-10-23-182639  largestProcess=WeChat            victims: (空)
```

**`victims` 全空** → 这些只是内存快照，**没有任何进程被 Jetsam 杀掉**。排除内存不足。

**⑤ 抓 syslog（120 秒，65 MB）——游戏全程活着**

```powershell
python -X utf8 -m pymobiledevice3 syslog live   # 后台跑 120 秒
```

关键发现：

```
20:44:34 → 20:44:49  DeltaForceClient(415) 每 1-2 秒都有活动
  · AmbientSound / SystemSoundsAndHaptics 音频 assertion 持续
  · ACE 联网正常：nj.cschannel.anticheatexpert.com 解析成功
  · runningboardd 没有任何 "exited" / "Removing assertion"
  · 窗口结束时游戏还活着
```

**窗口内没闪退**（说明闪退不是每分钟必发，或者那次没进到会闪的地方）。

### 6.3 结论：进程自己 `exit()` 了

三种"回桌面"的日志特征对比：

| 方式 | 日志特征 | 你这里 |
|---|---|---|
| 崩溃（SIGSEGV/SIGABRT） | 必生成 `.ips`，含 `Exception Type` | ❌ 没有 |
| 被系统杀（Jetsam/watchdog） | JetsamEvent 有 victims / watchdog 记录 | ❌ 没有 |
| **进程自己 `exit()`** | **什么日志都没有，干净消失** | ✅ **完全符合** |

**只有 ACE 主动调 `exit()` 才能解释"没有任何日志的突然回桌面"。**

### 6.4 因果链：`/var/jb` 残留

**关键认知：「重启后不越狱」≠「清除越狱」**

Dopamine 是**半不完美越狱**：

- 重启 → 内核补丁失效，Dopamine 不再运行
- **但 `/var/jb` 目录是写到磁盘上的，重启不会删**

ACE 检测逻辑是**扫文件系统**，只要 `/var/jb` 存在就判定越狱环境 → 调 `exit()`。**与 Dopamine 是否运行无关。**

**证据**：用户的环境检测报告里早就写着：

```
⚠ 越狱残留    /var/jb · /private/preboot
```

### 6.5 解决办法

**Dopamine → 打开 App → 右上角设置/齿轮 → `Remove Jailbreak`（或 `Restore RootFS`）**

效果：
- ✅ 删除 `/var/jb` 和所有越狱文件
- ✅ 保留 App、照片、账号数据
- ⚠️ 之后需重跑 Dopamine 才能恢复越狱

**清完重启 → 插 USB → 验证：**

```powershell
python -X utf8 -m pymobiledevice3 afc ls /        # 不应再有 /var/jb
```

### 6.6 如果清除越狱后**还是**闪退

说明 ACE 检测的是别的东西，按以下顺序排除：

1. **卸载 FindMy**（我们的伪装 App，Bundle ID `com.apple.findmy`，可能与系统 App 冲突被检测）→ 再试游戏
2. **检查 TrollStore 痕迹**（`/var/containers/Bundle/Application` 下的签名异常）
3. **App Store 更新游戏**（服务端可能要求新版本）
4. **检查存储空间**（训练营要加载地图资源）

## 12. 坑与注意事项

1. **不提交/推送，除非用户明确要求**
2. **改完先跑 preflight**（framework 声明 + import 路径）
3. **`SecTask.h` 是私有头** → 自己 `extern "C"` 声明原型，但链接仍需 Security.framework
4. **`@property (readonly)` 不自动合成 ivar** → 必须在 ivar 块里显式声明
5. **`HOST_NODENAME` 在 iOS SDK 可能未声明** → `#ifndef` 兜底（=5）
6. **`mach_vm_remap` 的 `src_task` 必须是 task port**（这是白米饭也要靠 KFD 的原因）
7. **`task_for_pid(getpid())` 永远成功**，不能当权限证据
8. **TrollStore ≠ 越狱**：Frida 能力来自 Dopamine
9. **Dopamine 半不完美**：重启掉越狱，但 `/var/jb` 文件留着
10. **27042 转发会假活**：设备断开后进程还在监听，要 kill 重起
11. **构建失败会跳 run number**，包版本看 `MFBuildStamp`
12. **局域网 IP 是 192.168.2.4**
13. **`crash pull` 第一个参数是输出目录**，不是文件路径；用 `--match` 过滤
14. **`syslog live` 抓不到内核 SIGKILL**，只能证明进程是否还活着
15. **USB 排查**：PnP 显示 OK 但 `usbmux list` 空 → 重启 `Apple Mobile Device Service`；iPad 锁屏时 USB 数据通道关闭
