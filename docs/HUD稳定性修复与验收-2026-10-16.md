## 根因与改动

| 问题 | 已确认根因 | 修复行为 |
|---|---|---|
| 菜单不能点、小球不能展开 | 菜单窗口在 context 初始化时一度报告忽略触摸；球整个区域提前进入拖动分支，点击不送给 ImGui | 菜单从分配开始固定交互身份；球和标题先等待 8pt 拖动阈值，轻点发送一次完整点击，拖动只移动窗口 |
| 穿透区仍触发菜单、异指误释放 | UIKit 与全局 HID 起点判定不一致；私有 HID 字段硬编码、窄 ID 与距离兜底可能混淆触点 | 真实 HID 工厂探针校验字段；完整 32 位 identity 所有权；空白起点拒绝、异指不能借用主触点；取消清掉队列与 ActiveID |
| 菜单遮挡范围过大 | 页签上报整页为命中区域，收起仅改 ImGui 内容，原生窗口仍占大面板范围 | 可见控件矩形裁剪至 child 视口，弹窗与滚动条显式登记；收起实际把原生窗口改为 56×56，展开恢复 348×520 |
| 卡顿与输入延迟 | 主队列直接调用可能等待 drawable 池的 nextDrawable；ImGui 时间步长不正确；颜色拖动反复同步保存 | 每个 overlay 专用串行队列获取 drawable，最多一个待获取、两份 GPU 额度；UI/ImGui 留在主队列；generation 丢弃旧帧；真实单调 DeltaTime；保存按钮统一落盘 |
| 退出失败、假运行、重新启动错乱 | 提前删 PID 丢失活进程；旧 PID 只查存活；全局退出通知无 session 隔离；硬退出也依赖主队列 | PID 记录含路径、启动时间、session；确认死亡或身份不符后清理；控制队列在主线程收尾之前安排 1.2 秒退出截止；启动/取消/停止串行并回收子进程 |
| 启动后异常 | MFGameReader 声明了 load/save/summary，但没有实现；绑定后调用触发 unrecognized selector | 补齐三个方法；三基址快照绑定真实目标 PID、完整路径及启动时间，目标变化时清空并重绑 |

布局使用固定标题、收起、退出、页签和保存栏，设置内容单独滚动。保留已有双窗口与 context 托管顺序；绘制窗口始终忽略触摸。删除会让一次点击同时作用于菜单和下层应用的“整面板双响应”设置。

## 苹果资料与穿透边界

- [UIView hitTest](https://developer.apple.com/documentation/uikit/uiview/hittest(_:with:)) 和 [point(inside:with:)](https://developer.apple.com/documentation/uikit/uiview/point(inside:with:)) 描述进程内的视图命中规则；返回 nil 本身不能证明另一个应用会收到触摸。
- [CAMetalLayer nextDrawable](https://developer.apple.com/documentation/quartzcore/cametallayer/nextdrawable/) 可能等待 drawable 池；把事后跳帧写在调用之后不能消除这次主线程阻塞。
- [TrollSpeed HUDMainWindow](https://github.com/Lessica/TrollSpeed/blob/main/sources/HUDMainWindow.mm) 用于核对窗口角色初始化，是私有接口的开源实现参考，不是苹果公开保证。

本轮可靠的交互路径是：绘制层全穿透、菜单窗口之外可操作、收起后旧面板区域释放。展开面板内部空白处是否能跨进程传给下层，仍必须在该 iPad 的实际托管环境触摸验收，不能仅用 simulator 的 pointInside 测试宣称已经通过。

## 功能完整度

逐项矩阵见 [功能差距审查-2026-10-16.md](功能差距审查-2026-10-16.md)。目前不能称作原版功能全部完成：真实名称、物资分类/盒子识别、真实骨骼、若干人物与物资字段偏移、UE4 数据链到绘制的衔接仍有缺口；观战/直播模式目前仅有设置占位，菜单已明示尚未接入。主题和“物理透视”的规格及实现也未完成。

本轮验证 HUD 基础设施与读取器实例管理，不把合成自检或基址保存测试当作真实游戏数据链通过。系统清理、Keychain、高级游戏模式与标识符修改的 root 业务通道和结果验证应单独处理。
