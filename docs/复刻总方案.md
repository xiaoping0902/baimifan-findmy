## 一、一句话目标

把白米饭的四层骨架——**伪装壳 → 主界面 → HUD 双窗口 → 内核读取链**——用自己的代码重写，通过 GitHub Actions 云构建出 IPA，装进已就绪的巨魔环境。**桌面点「查找」图标，打开的是我们的界面。**

## 二、伪装身份（v2 核心变更）

| 字段 | 取值 | 来源 |
|---|---|---|
| `CFBundleDisplayName` | **查找** | 用户指定（中文设备显示名） |
| `CFBundleIdentifier` | **`com.apple.findmy`** | [joeblau/apple-bundle-identifiers](https://github.com/joeblau/apple-bundle-identifiers)：`Find My (iOS 13+)` |
| `CFBundleName` | `FindMy` | 与系统应用同名 |
| `CFBundleExecutable` | `FindMy` | 与系统应用同名 |
| 主二进制名 | `FindMy` | PRODUCT_NAME |
| 内核选择页选项 | 自动 / landa / smith / physpuppet / 纯巨魔 | 与白米饭一致 |

**白米饭同款原理**：系统按「已注册的 bundle ID + 路径」启动可执行文件。同 bundle ID 经 TrollStore 注册后，`com.apple.findmy` 的路由指向我们的包，因此图标点开显示我方 UI。

> ⚠️ **已知代价**：原版「查找」App 可能无法再从桌面图标进入（与白米饭顶掉 iTunes Store 同理）。iCloud 侧的「查找我的 iPad」定位不受影响——那是服务端能力，不依赖本机 App。

## 五、技术架构

### 5.1 语言与框架

| 部分 | 用什么 | 为什么 |
|---|---|---|
| 全工程 | **Objective-C++（.mm）单二进制** | 与白米饭同构：ObjC 管 iOS 生命周期，C++ 管 ImGui/KFD |
| 主界面 | **UIKit 纯代码**（insetGrouped 卡片风） | 原生 = iOS 观感 + 满帧丝滑 |
| HUD 菜单 | **ImGui 1.93（C++）+ iOS 风格皮肤** | 用户指定「C++ 绘制 UI」 |
| 绘制层 | **ImGui DrawData → Metal → CAMetalLayer** | 60fps，白米饭同架构（已证） |
| 内核 | **felix-pb/kfd + wh1te4ever/kfund patchfinder** | 见 5.3 |
| 工程生成 | XcodeGen（`project.yml`） | 声明式，免手工 .xcodeproj |
| 构建 | GitHub Actions（macOS runner） | Windows 无 Xcode |

### 5.2 运行形态（双角色）

```
点桌面「查找」图标
  → 主进程（普通角色）：主界面控制台
       ├─ 按钮「启动内核」→ KFD 链（漏洞→root→kernel port→task 枚举）
       ├─ 按钮「清理系统残留 / 清理 Key / 防封设置」
       └─ 按钮「启动悬浮窗」→ posix_spawn 自己，带 -hud
             → HUD 进程（HUD 角色）：不显示主界面
                 创建两个窗口 → HUDImguiWindow（菜单，状态栏−20，可触摸）
                              → DrawingWindow（透明绘制，状态栏+20，忽略触摸）
                 两窗交给 SBSAccessibilityWindowHostingController 托管（跨 App 悬浮）
```

### 5.3 ★ 内核链硬约束（来自 `kfd-集成调研.md`）

| # | 约束 | 处置 |
|---|---|---|
| 1 | **16.6.1 上唯一可用的 PUAF 是 `puaf_landa`**（physpuppet 16.4 修复、smith 16.5.1 修复、landa 17.0 才修） | 默认且固定 landa |
| 2 | **必须 `kread_sem_open` + `kwrite_sem_open` 成对**（`krkw.h` 有 assert；kqueue_workloop_ctl 在 16.5+ 被表位禁用） | 固定组合 |
| 3 | **上游 kfd 原样烧进去会立刻失败**：`kern_versions[]` 只有 4 条（16.5/16.6/macOS），**没有 16.6.1、没有 T8112(M2)** → `unsupported osversion` → `sleep(30)` + `exit(1)` | **走 kfund 运行时 patchfinder 路线（路线 A）** |
| 4 | **M1/M2 内核链接基址不同**：`ARM64_LINK_ADDR` 必须 `0xFFFFFE0007004000`（上游硬编码 iPhone 值） | 运行时按机型取 |
| 5 | **`T1SZ_BOOT` 对 T8112 应取 17** | 运行时变量 |
| 6 | **assert 失败 = 卡 30 秒后闪退** | 桥接层做机型/版本预检 + 改 assert 宏为错误返回 |
| 7 | **必须单 TU include `libkfd.h`**（函数无 `static`，多 TU = 重复符号） | 纯 C 桥接层 `kfd_bridge.c` |
| 8 | **`common.h` 的 `min/max` 宏会污染 C++** | 业务 .mm 只 include 干净头文件 |

**落地写法**：
```c
u64 kfd = kopen(2048, puaf_landa, kread_sem_open, kwrite_sem_open);
```
`puaf_pages`：8GB 机型从 2048 起步，不稳降 1024/512；landa 支持同进程重试。

### 5.4 ★ ImGui 硬约束（来自 `imgui-集成调研.md`）

| # | 约束 | 处置 |
|---|---|---|
| 1 | 官方**没有** iOS 输入后端，只有 `imgui_impl_metal.mm` | 自写 UITouch → ImGuiIO 映射 |
| 2 | 只编 **5 个核心 cpp + `imgui_impl_metal.mm`** | 别把整个 `backends/` 塞进工程 |
| 3 | **1.92+ 动态字体体系**：不传 GlyphRanges、不 Build()、不用「2×字号+FontGlobalScale=0.5」老配方 | 照新版写 |
| 4 | **多视口（多 OS 窗口）在 master 分支不存在** | HUD 只能画在单一 layer 里 |
| 5 | 悬浮场景建议**自建 `CAMetalLayer`**（透明 + 按需重绘），非 MTKView | 透明绘制窗走这条 |
| 6 | 触摸要接全 **4 个回调**（含 `touchesCancelled`），否则按钮永久卡住 | 主触点策略 + 后台 `AddFocusEvent(false)` |
| 7 | `io.IniFilename` 在 iOS 沙箱不可靠 | `NULL` 或指到 Documents；HUD 窗加 `NoSavedSettings` |

**编译单元**：`imgui.cpp` / `imgui_draw.cpp` / `imgui_tables.cpp` / `imgui_widgets.cpp` / `imgui_demo.cpp`（可选）+ `backends/imgui_impl_metal.mm`。

## 十一、缺口处理策略

分析包明确标注【未证】的项（实体完整布局、等级/价值偏移、骨骼来源、防封随机算法、KFD 实机结果）：

1. 复刻版一律按【已证】字段起步（相机结构体、`+0xE68` 数量、`+0x220` 坐标、投影数学都已证）；
2. 【未证】字段全部做成**可配置偏移表**（`Game/Offsets.h` 一张表改一处）；
3. 不阻塞主线：App 骨架 / HUD / 清理 / 内核链 全部独立于这些缺口；
4. M4 真机迭代时用自检工具校准（比对读数 → 调表 → 复测）。

**已证偏移（可直接用）**

| 项 | 值 | 来源 |
|---|---|---|
| 相机结构体 | `[对象+0x40]` → `+0x10` X / `+0x14` Y / `+0x18` Z / `+0x20` 俯仰 / `+0x24` 偏航 / `+0x28` 横滚 / `+0x2C` FOV | `读取与绘制_实现全解.md` §3.1 |
| 实体数量 | `+0xE68`（int） | 同上 §3.2 |
| 实体世界坐标 | `+0x220`（3 float） | 同上 §3.3 |
| 投影 | 角度×`0.0174533`，深度<`0.1` 返回哨兵 `-9999`，焦距 `tan(FOV·π/360)` | 同上 §5.1 |
| 物资标签 | `%s\n等级[%d]\n价值[%d]\n[%.1fm]`，距离 `sqrt(dx²+dy²+dz²)/100` | 同上 §3.4 |
| 配色 | 等级 3/4/5/6 各自色；非 3–6 且价值>9999 → 3 级色强调 | `读取绘制与物资分类分析.md` §4 |
