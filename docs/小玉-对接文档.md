## 3. 物品 ID 十进制编码（头 / 甲 / 包 / 武器）

```
11010005002
│└┬┘ └┬┘
│ │   └── 第 8 位 = 等级 1..6
│ └────── 第 2-4 位 = 类型码
└──────── 首位固定 1
```

| 类型码 | 含义 | 示例 |
|---|---|---|
| 101 | 头盔 | `11010005002` → 头 5 |
| 105 | 护甲 | `11050006002` → 甲 6 |
| 108 | 背包 | 未见实样 |
| 802 / 810 | 武器 | `18020000002` / `18100000009` |

**合法性区间**：`[10000001, 0x4A87F317F]`

**5 档配色**（从参照二进制 `0x10062E49C` 原样读出）：

| 等级 | RGB |
|---|---|
| 2 | (0, 255, 0) 绿 |
| 3 | (135, 206, 250) 天蓝 |
| 4 | (122, 103, 238) 紫 |
| 5 | (255, 219, 0) 黄 |
| 6 | (255, 0, 0) 红 |

## 6. Frida 调试手册（本机实测流程）

### 6.1 连接

```powershell
# 1) 确认设备
py -3.12 -m pymobiledevice3 usbmux list

# 2) 端口转发（保持后台常驻）
py -3.12 -m pymobiledevice3 usbmux forward 27042 27042

# 3) 自测
py -3.12 -c "import frida; d=frida.get_device_manager().add_remote_device('127.0.0.1:27042'); print(len(d.enumerate_processes()))"
```

### 6.2 两条注入路线

| 路线 | 结果 |
|---|---|
| `attach(pid)` 到**系统启动**的游戏 | ❌ `unexpected error while resuming process: (os/kern) failure` |
| `spawn([bundle])` 后 `resume` | ✅ 稳定，数据连续 2 分钟以上 |

### 6.3 找进程不要用名字

frida 传回的进程名是乱码（`����`），必须走 bundle id：

```python
for a in dev.enumerate_applications():
    if (a.identifier or "") == "com.tencent.tmgp.dfm" and getattr(a, "pid", 0):
        pid = a.pid
```

### 6.4 探针脚本

| 脚本 | 用途 |
|---|---|
| `tools/frida_full.js` | 全字段轮询（每 4s），JSON 输出 |
| `tools/frida_verify.js` | 偏移逐条核对 |
| `tools/frida_players.js` | 只挑角色，核对 UIN/名字/骨骼 |
| `tools/frida_equip.js` | 装备槽原始 ID |

**注意**：`console.log("%d")` 在 frida 里**不做替换**，一律 `send({...})` + Python `json.dumps`。

### 6.5 USB 掉线的兜底

本机 USB 链路不稳（游戏一跑就可能 `usbmux = []`）。兜底方案：**让悬浮窗自己写日志**。

```
/var/mobile/Media/mf-debug/mf-live.txt
```

拉取：

```powershell
py -3.12 -m pymobiledevice3 afc pull mf-debug/mf-live.txt .\mf-live.txt
```

日志每行形如：

```
A[104] 0x16eb08000 pos=29905.2,27670.8,102.5 idx=65535 enc=0 team=0 ai=0 bone=75 eq=11010006002/11050006002
```

## 7. 已踩过的坑（务必先读）

| 坑 | 现象 | 结论 |
|---|---|---|
| **写了没人调用的代码** | 队伍/人机/头甲/死人全不生效 | `MFUEReader.enumerateActors` **从来没被调用**，绘制走 `MFGameReader`。改功能前先确认调用点 |
| 骨骼数组取错偏移 | 骨骼永远不出现 | `Mesh+0xA18` 是缓存数组（常空），真正的在 **`Mesh+0x750`** |
| FString 布局 | 名字永远 null | 这里 **Data 在前、Num 在后**（`+0x470` / `+0x478`），和 UE4 标准相反 |
| 装备槽固定偏移 | 有时读到、刷新后读不到 | 槽位地址会漂，改成**整块 2KB 扫描物品 ID** |
| `readU64` 返回类型 | `gw.isNull is not a function` | frida 的 `readU64()` 返回 UInt64，需要指针语义时用 **`readPointer()`** |
| 严格读跨页 | 480 字节装备块整段作废 | 用 `readRemotePartial` |
| 注释里出现 `*/` | 编译报 unknown type name | 注释里不要写 `kread*/kwrite`，preflight 已加检测 |
| CRLF 文件 | `edit` 工具匹配失败 | 用 Python 做 LF 归一化替换 |
| 菜单文件名乱码 | 只在 PowerShell 预览里 | 文件本身是 UTF-8，读取时指定编码即可 |

## 8. 构建与发布

```powershell
git add -A
git commit -m "feat(esp): ... (M5.xxx)"
git push origin fix/hud-reliability     # 任意 push 都会触发 CI
```

- CI：GitHub Actions `build.yml`，tag `ipa-${{ github.run_number }}`，版本 `M5.$RUN`
- 等待并下载：`py -3.12 -X utf8 _takeover\wait107.py <N>`
- 本机分发：`FindMy-ipa<N>.ipa` 放到 `C:\Users\xiaoping\Desktop\ipa-serve`，
  `http://192.168.2.4:8080/FindMy-ipa<N>.ipa`
- 版本戳可核对：`MFBuildStamp = <sha>-r<N>`、`MFBuildSHA = <full sha>`

**提交前必跑**：

```powershell
py -3.12 -X utf8 scripts\preflight.py
```

它会查：缺头文件、注释里的 `*/`、`calloc` 没 `<stdlib.h>`、CoreFoundation 未链接等。
