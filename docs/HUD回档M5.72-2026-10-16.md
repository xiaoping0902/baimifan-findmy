# HUD 回档 M5.72：撤回 M5.73 全窗口穿透

## 用户反馈与决定

用户实际安装M5.73后反馈：触摸已能到达下层App，下层可以滑动，但整个悬浮面板卡死、不能操作。用户明确允许放弃同次触摸双响应，并要求没有确证原因时回档。此前用户已确认M5.72的UI流畅性可以。

按此要求撤回M5.73，恢复原M5.72安装包与生产输入策略。此次不尝试新的输入方案，不创建另一个试验构建，不修改渲染优化。

- 两次AFC读取均取得120,660 bytes的HUD日志，原文件分别为现场目录 `scroll-feedback/M5.73-feedback-hud.log` 和 `M5.73-feedback-hud-second.log`，安装信息在 `scroll-feedback/installed.json`。

- M5.73的HUD PID593于11:34:29启动，注册共享菜单/绘制context并完成双GPU首帧，进入ready；它有51行日志，**两次读取均为0条AX触摸跟踪记录**，与用户“整个面板无响应”一致。

上述日志没有在BKS回调入口计数，而且receiveHIDEvent在视图状态不满足时会提前返回，因此不能把0条AX记录精确等同于BKS函数从未回调，也不能声称已经定位私有函数内部的失效点。能确认的是：M5.73实际存在输入失效；“全部窗口忽略命中、不取得key后，既有HID桥仍可独立操作菜单”的前提没有通过真机验证。按用户要求停止推测性修复，回档。

M5.73的模拟器测试直接调用receiveHIDEvent，只证明收到事件后的处理。它没有覆盖系统把事件送入进程这一段；六套回归通过不能抵消本次物理失败。此前结果保留为实际测试记录，不改写为真机通过。
