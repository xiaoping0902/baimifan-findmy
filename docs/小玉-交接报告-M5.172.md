# 小玉 · 交接报告（M5.172）

> 项目：三角洲行动 iOS 悬浮窗（伪装名「查找」，版本号 `M5.x`）
> 目标：`com.tencent.tmgp.dfm`，实测 iPad14,4 / iPadOS 16.1 / 越狱 Dopamine 3.0.12
> 报告时间：2026-10-26
> 当前构建：**M5.172**（`fc7857a-r172`，SHA-256 `0E2DFA1B…2CE6D96E`）

---

## 一、一句话现状

**小玉现在只靠自己的 KFD 读游戏内存**：不需要 task port、不需要 Frida、不需要外部 agent。
数据分两层刷新：**相机和坐标每帧**，**队伍/头甲/血量/武器每秒**。

---

## 二、架构（当前真实链路）

```
┌─────────────────────────────────────────────────────────┐
│ 小玉 HUD 进程（FindMy.app，TrollStore 安装）               │
│                                                         │
│  KFD（内核读）：pid → proc+0x18 → task+0x08 → vm_map+0x28 │
│                        → pmap+0x40 → tte → 三级页表遍历   │
│                                                         │
│  MFGameReader.readFrameWithSize:                        │
│      ├─ readCamera:                  ← 每帧              │
│      ├─ readEntitiesWithCamera:      ← 每帧（读坐标）     │
│      │      属性缓存 1.0~1.5s（按 Actor 错开 TTL）        │
│      └─ readLootWithCamera:          ← 物资/盒子          │
│                                                         │
│  MFDrawingLayer（ImGui + Metal，60fps）                  │
└─────────────────────────────────────────────────────────┘
```

**已彻底移除**：UDP 外部数据源（`MFExternalFeed`）不再启动、不再作为绘制来源。

> 说明：`tools/agent_esp.js` 是**电脑端调试工具**，通过 Frida 注入游戏进程读数据。
> 它**不参与 App 绘制**，也不会打进 IPA。

## 三、为什么之前一直"修不好"——5 个致命错误

这一节是本次交接最重要的部分。所有现象都在这五条里。

### 错误 1：代码写进了没人调用的函数

- **现象**：改了过滤/头甲/人机，画面完全没变化
- **根因**：`MFUEReader.enumerateActors` 在全仓库**只有定义、零处调用**
- **证据**：`Select-String -Pattern "enumerateActors"` 只命中 1 行（定义）
- **修法**：把逻辑搬进真正被调用的方法（`MFGameReader.readEntitiesWithCamera`）
- **版本**：M5.155

### 错误 2：绘制数据源顺序反了

- **现象**：自己照画、子弹有框、头甲空白，且**一下有一帧一下没有**
- **根因**：`acquireFrame` 先试外部 agent 的 UDP 包，**有包就直接 return**；
  而那个包只有坐标，没有队伍/头甲/血量。KFD 那条（字段齐全）永远轮不到
- **证据**：`MFDrawingLayer.mm:382` 原来的注释写着"外部数据源——真机上唯一能通的路"
- **修法**：顺序改为 KFD 优先 → agent 兜底 → UE4 链；再后来直接把 agent 摘掉
- **版本**：M5.161（调序）、M5.162（彻底移除）

### 错误 3：每帧都做内核读 → 看门狗杀进程

- **现象**：启动后**连着重启两次**
- **根因**：KFD 变成主源后，`readFrameWithSize:` 每帧（60 次/秒）跑一遍，
  每次读几十个 Actor × 每个 10+ 字段，还扫 2KB 装备槽 → 主线程被拖死
- **修法**：分层读取——**坐标每帧、属性每秒**
- **版本**：M5.163（整帧缓存，止损）、**M5.164（分层读取，正解）**

### 错误 4：整帧缓存 → 框跟不上准星

- **现象**：卡顿，框滞后于目标
- **根因**：连**相机**一起缓存了 250ms
- **修法**：相机和坐标每帧读，只缓存"一秒内不会变"的属性
- **版本**：M5.164

### 错误 5：FString 布局与 UE4 相反

- **现象**：名字永远是 `null`
- **根因**：这里的字符串是 **`Data@+0x470`、`Num@+0x478`**（指针在前），
  UE4 标准是 `Num` 在前
- **证据**：真机 frida 解码出 `"忧郁的小平大帅"`
- **版本**：M5.156

### 附：装备槽偏移会漂

- **现象**：同一地址这局能读到、刷新后就空
- **根因**：人机一刷新，装备组件布局变了
- **修法**：**整块 2KB 读进来，在内存里扫"符合物品 ID 格式"的值**
- **版本**：M5.157

## 五、物品 ID 十进制编码

```
11010005002
│└┬┘ └┬┘
│ │   └── 第 8 位 = 等级 1..6
│ └────── 第 2-4 位 = 类型码
```

| 类型码 | 含义 | 实测样例 |
|---|---|---|
| 101 | 头盔 | `11010004001` = D6战术头盔 |
| 105 | 护甲 | `11050006002` = 6 级甲 |
| 108 | 背包 | 表内 26 条 |
| 802 / 810 | 武器 | `18020000002` = M4A1突击步枪 |

**合法性区间**：`[10000001, 0x4A87F317F]`

**内置名字表**：`app/Sources/Game/MFItemNames.{h,mm}`，**891 条**（从《内置字典ID对应表》生成），
二分查找，`MFItemNameForID(uint64_t)`。

## 七、剔除链（当前生效）

| # | 剔除 | 判法 | 位置 |
|---|---|---|---|
| 1 | 自己 | `item == gMFUELocalPawn` | MFGameReader |
| 2 | 自己（兜底） | `mesh == gMFUELocalMesh` | MFGameReader |
| 3 | 自己（兜底 2） | 距离 < 2.0m | MFGameReader |
| 4 | 队友 | `TeamID == 自己TeamID` 且 `PlayerState != 0`（菜单「队友」可反） | MFGameReader |
| 5 | 死人 | `actor+0xDC8 != 0` | MFGameReader |
| 6 | 观战/未激活 | `PS+0x4C0 & 1` | MFGameReader |
| 7 | **非角色** | 无 Mesh / 无骨骼 / 骨数 < 20 | MFGameReader |

第 7 条最关键：**子弹、投掷物、箱子、场景物件都有 RootCoordinate 和坐标**，
只有骨骼判据能把它们挡掉。

## 八、数据刷新策略（M5.164 起）

| 数据 | 频率 | 代价 |
|---|---|---|
| 相机 | 每帧 | 1 次读 |
| 每个角色坐标 | 每帧 | 1 次读（12 字节） |
| 队伍/头甲/血量/武器/骨骼/是否角色 | 按 Actor 缓存 **1.0~1.5s**（TTL 按地址错开） | 每角色约 10 次读，但每秒一次 |

效果：20 个角色时，每帧内核读从 200+ 次降到 **20 次**；框跟手，属性不闪。

## 十、Frida 调试手册（电脑端）

```powershell
py -3.12 -m pymobiledevice3 usbmux list                        # 看设备
py -3.12 -m pymobiledevice3 usbmux forward 27042 27042         # 转发
```

| 路线 | 结果 |
|---|---|
| `attach(pid)` 到系统启动的游戏 | ❌ `unexpected error while resuming process` |
| `spawn([bundle])` 后再 `resume` | ✅ 稳定 |

**进程名是乱码**（`����`），必须用 bundle id 找：

```python
for a in dev.enumerate_applications():
    if (a.identifier or "") == "com.tencent.tmgp.dfm" and getattr(a, "pid", 0):
        pid = a.pid
```

**注意**：`console.log("%d")` 在 Frida 里不替换，一律 `send({...})` + `json.dumps`。

## 十三、已知环境风险

1. **USB 链路不稳**：游戏一跑，`usbmux` 常掉（`devices: 0`）。
   拔插/重启 Apple 服务可恢复；Frida 调试请"spawn 后立刻抓"。
2. **反作弊**：游戏在前台时 Frida 注入常被掐（`connection closed`）。
   **这是 agent 只能做调试、不能做产品的原因之一。**
3. **看门狗**：任何主线程长任务都会被 iOS 杀掉（0x8badf00d），内核读务必限频。
4. **内核句柄独占**：`kernel.owner` 记录持有 pid，第二个同类工具会拿到 `-4`。
